# Security Policy

## Supported scope

PACA-Plus-Plus-New is a research prototype. Security reports are welcome for the repository, reference implementations, CI workflows and documented deployment examples. A successful unit test or workflow run is not a security certification.

## Reporting a vulnerability

Please do not disclose exploitable details, credentials, private data or proof-of-concept payloads in public issues or pull requests.

Use GitHub's **Report a vulnerability** / private vulnerability reporting option in the repository's **Security** tab when it is available. If private reporting is not enabled, contact the repository maintainer privately through the GitHub profile before sharing technical details. Do not send secrets or live customer data.

Include the affected commit or release, affected component, prerequisites, impact, a minimal reproducible description, and any proposed mitigation. Allow the maintainer a reasonable opportunity to investigate and coordinate a fix before public disclosure.

## Scope and expectations

Reports should distinguish a demonstrated vulnerability from a design limitation or a documented bypass. Do not test against systems, accounts or data that you do not own or have explicit permission to assess. The project does not currently claim complete mediation, production provider enforcement, host isolation or independent security certification.
